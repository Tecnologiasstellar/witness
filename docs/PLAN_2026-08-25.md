# Day-four plan — 2026-08-25

Owner brief from AV at close of 2026-08-24, expanded into decisions and ordered slices. Timeline anchor: TestFlight by Sep 6, submission Sep 15.

## 1 · Architecture to scale card production (staging/prod stays as is)

**What already holds:** `WitnessCore` validates every record in CI; content is data (`species.json`); Debug→`witness-staging`, Release→`witness-prod` with migrations staging-first (D-018). Nothing to re-architect.

**What scaling needs:**
- **`tools/new-card.py`** — scaffolds a card from a species name: empty v2-shaped JSON with TODO markers, a source-verification checklist, the five image-prompt templates pre-filled from the locked style template, and a rights-record stub. Turns card production from memory into mechanical steps.
- **Split `species.json` into `Resources/catalog/<id>.json`** loaded by `BundledSpeciesCatalog` — one file per card so 30 cards don't collide in one 4,000-line file and PR review reads per-species.
- **CI content gate**: a `swift test` already rejects invalid records; add a CI step that fails when a record marked `approved` has unverified URLs (curl check script).
- Bundled catalog remains the delivery mechanism for v1 (D-015). Remote catalog only when release-coupled publishing hurts.

## 2 · Content process — creating, keeping, saving cards

- Pipeline doc gains the **v2 stages** (already practiced, now written): sources → stats/threats/regions/insight/programs (all curl-verified) → story 120–220 words → five plates (hero, habitat, head study, behavior, human-scale) → accuracy review → rights record → validator → PR.
- **Originals** stay in the Higgsfield account library (job IDs recorded per asset); the repo keeps 1400px derivatives. `docs/media/` is the rights ledger.
- **Approval = PR review.** A card is `prototype` until AV (or a conservation reviewer later) flips `editorial.state` to `approved` in the PR. The production validator already enforces this — no new tooling needed, the gate exists.
- **Cadence to 30:** ~4 cards/day from Tier 1 backlog ≈ launch catalog complete by Sep 1, leaving buffer before TestFlight.

## 3 · Cron jobs, admin approval, and notifications

Three distinct needs, three honest answers:

- **Users learning a new card is live → LOCAL notifications, not server push.** The catalog is bundled and rotates daily on-device, so a daily local notification ("Today's species is waiting") at a user-chosen time needs zero infrastructure, works offline, and ships this week. APNs server push (certs, tokens, backend sender) buys nothing at MVP scale — deferred post-launch, when remote catalog delivery arrives.
- **New cards being *created* on a schedule → a scheduled cloud agent.** A weekly Claude routine drafts the next batch of cards through the full pipeline and opens a PR. AV's merge *is* the admin approval. (Set up via `/schedule` when AV wants it; manual production continues meanwhile.)
- **Server-side cron** (Supabase pg_cron) — not needed for v1; noted for post-launch count-digest jobs.

**Tomorrow builds:** reminder opt-in in the Index (time picker, `UNUserNotificationCenter`, primer after first witness per D-008), plus `reminder_enabled` event.

## 4 · User database, information, engagement

Confirming the standing decisions (D-015, D-017) as the v1.0 answer:
- **No accounts. No personal data.** Identity is an anonymous install UUID. The backend stores only: witness events (install id + species + day), analytics events (name + install id + coarse metadata). RLS makes raw rows unreadable to clients; aggregates are the only read surface.
- **Engagement measurement** = the events table: ritual completion, witnesses, helping starts, shares, paywall views, purchases (via RevenueCat). Weekly SQL over staging/prod answers retention questions — no third-party analytics.
- **App Privacy label**: "Data not linked to you — identifiers, usage data." Nothing else. This is a marketable strength; the privacy policy will say it plainly.
- **Post-v1 path** (not now): iCloud/CloudKit sync of the private archive for device migration — still no accounts.

## 5 · Private notes

- Notes live **on-device only** (`witness-archive.json`, file protection enabled), are **never** uploaded, never in analytics, and excluded from share plates (UI-test-enforced since Weekend Zero). Only the *event name* `reflection_saved` is logged.
- They ride the user's own device backup (iOS backs up app data) — durability without our servers ever seeing content.
- v1 additions tomorrow: state this in the Index privacy section and the privacy policy; per-note viewing already exists via Notes. Deletion: editing a note to empty deletes it (verify; make true if not).
- Post-v1: optional note export (user-initiated file), CloudKit private-DB sync.

## 7 · App icon v1.0 — Claude Design guidelines

- **Identity**: the Atlas museum plate. Warm-paper field (`#F1E8D5`), deep ink (`#25231F`), sepia (`#624936`) — no gradients-for-gradients'-sake, no gloss.
- **Mark direction A (recommended)**: the field-mark reticle (the app's witness glyph) drawn as an engraved instrument — simple, ownable, meaning-dense ("to sight, to witness").

- **Constraints**: no text; must read at 60 px and at 1024; centered single mark with generous margin; provide iOS 18 light / dark / tinted variants (dark = ink field with paper mark); flat, print-like, no drop shadows.
- Process: generate 3–4 candidates with Claude Design / Higgsfield in one session, pick on the phone home screen at real size.
